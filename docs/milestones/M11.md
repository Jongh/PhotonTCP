# M11 — 모바일(Android) 1급 지원: Kivy 앱 골격 + APK 빌드 파이프라인

## 목표

이 마일스톤이 끝나면 PhotonTCP가 **안드로이드 폰에서 한 피어로 동작할 수 있는 상태**가 된다.
`DisplaySink`/`CameraSource` 모바일 어댑터와 Kivy 앱 골격이 생겨 폰이 화면·카메라를 모두 쥔 채
세션을 구동하고, `buildozer.spec` + 문서화된 빌드 경로로 **APK 산출물이 나온다**. 동시에
`qr/decode.py`의 cv2 하드 의존이 **디코더 백엔드 seam**으로 풀려, cv2가 없는 플랫폼에서도
패키지가 import되고 다른 디코더를 꽂을 자리가 생긴다. 실기(폰+PC) 사인오프 **실측 자체는 이번
범위 밖**이며, 이 마일스톤은 그 실측을 "장비가 없어서 못 함"에서 "설치하고 실행하면 됨"으로
바꾸는 것을 목적으로 한다.

## 배경

3차 회고(`docs/reports/retro.md`, 2026-09-08)의 최우선 `미결`에서 곧장 나온다:

- **v1.0 수동 사인오프 실측이 3사이클 연속 이월**(M8·M9·M10-review). 하니스·게이트 기준·문서
  (`docs/v1.0-signoff.md`)는 전부 갖춰졌고, 막고 있는 것은 코드가 아니라 **화면+카메라를 가진
  두 번째 기기**다. 폰은 그 두 번째 기기의 가장 현실적인 형태다.
- 사용자 요구(2026-09-08): "모바일 디바이스에서 테스트가 가능하도록 빌드". 타깃 경로는
  **Android APK (Kivy + buildozer)**, 범위는 **모바일을 1급 지원 대상으로** 확정됐다.
- **구조적 준비는 이미 돼 있다**: `photontcp/optical/devices.py`의 `DisplaySink`/`CameraSource`가
  하드웨어 경계이고 `cv2_devices.py`가 그 계약의 선례다. 세션·신뢰성·앱 계층은 `Channel`에만
  의존하므로 어댑터 한 쌍이면 상위 계층은 한 줄도 바뀌지 않는다.
- **막는 것은 아래층이다**: `qr/decode.py`가 모듈 상단에서 `import cv2` 한다(M8-impl 후속 메모 1이
  이미 "패키지 전체 cv2-옵셔널 미달성"으로 남긴 항목). p4a의 opencv 레시피는 무겁고 실패 여지가
  있어, 디코더를 교체 가능한 seam으로 만들어 두는 것이 이번 이식의 **위험 분산**이다.
- 같은 회고의 2순위 잔여 둘도 비용이 작아 이번 사이클에 함께 닫는다 — **Micro-QR 원천 제거**
  (M10-review 권장 1: 원인은 디코더가 아니라 `segno.make(..., micro=True)` 기본값)와
  **`__version__` 단일 원본 불일치**(0.1.0 vs pyproject 0.10.0).

### 이번 사이클이 닫는 단위 / 이후로 이월하는 단위

범위가 한 사이클을 넘는 방향이므로 경계를 여기서 못박는다.

**이번 사이클 (M11)**

1. 디코더 백엔드 seam — cv2 지연 import + 백엔드 등록/선택 (공개 계약 불변)
2. 세션 구동 로직의 헤드리스 추출 (`run_peer`) — CLI 예제와 모바일 앱이 같은 코드를 쓴다
3. Kivy `DisplaySink`/`CameraSource` 어댑터 + 앱 골격 (role·scale·hold·camera 설정, 결과 표시)
4. `buildozer.spec` + 빌드 절차 문서 + **APK 실빌드 시도**(실패 시 폴백은 완료 기준 9)
5. 데스크톱에서 돌아가는 회귀 방어(어댑터 계약·`run_peer`·백엔드 seam 테스트)
6. 회고 2순위 잔여 정리(Micro-QR 원천 제거, `__version__` 일치)

**이후 사이클로 이월 (이번 범위 아님 — 명시)**

- **실기 사인오프 실측**: 폰에 APK를 설치해 체크 A(셀프체크)·체크 B(폰+PC 2-머신 왕복)를 돌리고
  수신율·요약 줄을 기록하는 일. 하드웨어·조명·정렬이 필요한 **수동 절차**다(M9가 정한 그대로).
- **대체 디코더 백엔드의 실제 구현**(ZXing via pyjnius 등) — 이번엔 *자리*만 만든다. opencv 레시피가
  실기에서 실패하는 것이 확인되면 그때 구현이 정당화된다.
- 앱 UX 다듬기(설정 영속화, 로그 뷰, 파일 전송 앱 UI), iOS, 서명·스토어 배포, 해상도/프레임율 튜닝.

## 태스크 상세

### M11-T01: `qr/decode.py` 디코더 백엔드 seam

- **변경 파일**: `photontcp/qr/decode.py`, `tests/test_qr.py`
- 모듈 상단의 `import cv2`를 **지연 import**로 바꾼다. `numpy`는 유지한다(p4a 레시피가 있고
  `encode_frame`·디바이스 계약이 이미 `ndarray`를 쓴다).
- 백엔드 개념을 도입한다: 이미지(`np.ndarray`)를 받아 `bytes | None`을 돌려주는 호출 가능 객체를
  이름으로 등록·선택한다(`register_decoder_backend(name, factory)` / `set_decoder_backend(name)` /
  `active_decoder_backend() -> str | None`). 기존 cv2 경로(전처리 캐스케이드 + 대체 detector 폴백)를
  통째로 `"cv2"` 백엔드로 **옮기기만** 한다 — 알고리즘은 손대지 않는다.
- 선택 규칙: 명시 선택이 없으면 등록된 백엔드를 **가용성 probe 순서로** 고른다(현재는 `"cv2"`
  하나). 가용 백엔드가 없으면 `decode_frame`은 **`None`을 반환하고 절대 raise 하지 않는다** —
  기존 None 계약·never-raise 불변을 그대로 유지한다(M10-review가 검증한 성질).
- thread-local detector 인스턴스·1회 probe 캐시 패턴은 현행 그대로 백엔드 안으로 이동한다.
- **공개 시그니처 불변**: `decode_frame(image, ...)`의 인자·반환 계약은 바뀌지 않는다. 기존
  단위 테스트(캐스케이드 identity·핫패스 단락·폴백 회복)가 그대로 통과해야 한다.
- 엣지: `_resolve_alt_kind` 등 내부 헬퍼는 `docs/v1.0-signoff.md`가 이름으로 호출하므로
  **이름을 유지**하거나, 옮긴다면 그 문서의 명령 줄을 같은 태스크에서 함께 고친다.

### M11-T02: 세션 구동 로직 헤드리스 추출 — `run_peer()`

- **변경 파일**: `photontcp/optical/peer.py`(추가), `examples/optical_link.py`(수정),
  `photontcp/optical/__init__.py`(수정)
- `examples/optical_link.py`의 `_drive_real_peer`(현재 398~557행)에서 **UI·argparse·print에
  얽히지 않은 부분**을 `photontcp/optical/peer.py`로 옮겨 `run_peer(channel, role, *, messages=…,
  timeout=…, on_event=None) -> PeerResult`로 만든다.
- `PeerResult`는 최소한 `established: bool`, `messages_match: bool`, `closed: bool`,
  `wall_seconds: float`, `passed: bool`을 담는 dataclass로 한다(현재 요약 줄이 출력하는 값들).
- 진행 상황은 **콜백 `on_event(kind, detail)`** 으로 흘린다 — CLI는 print, Kivy 앱은 라벨 갱신에
  쓴다. 라이브러리 코드에서 직접 print 하지 않는다.
- `examples/optical_link.py`는 `run_peer`를 호출하고 출력만 담당하도록 줄인다.
  **CLI 계약은 불변**이다: `--help`가 노출하는 인자 집합, 기본 인메모리 모드 exit 0,
  `--role`(`--real` 없이) argparse 거부(exit 2) — 완료 기준 4가 이를 방전한다.
- 채널 타입에 의존하지 않는다(`Channel` 인터페이스만) — 그래야 `OpticalChannel.pair()` 인메모리로
  테스트할 수 있다.

### M11-T03: `photontcp/mobile/` 패키지 + Kivy 어댑터

- **변경 파일**: `photontcp/mobile/__init__.py`(추가), `photontcp/mobile/kivy_devices.py`(추가),
  `pyproject.toml`(수정)
- `KivyDisplay(DisplaySink)`: `show(image)`가 2D uint8 QR 비트맵을 Kivy `Texture`로 올려 위젯에
  띄운다. 프레임 교체 의미(마지막 프레임만 유효)를 지킨다. 렌더는 **메인 스레드에서** 일어나야
  하므로 `Clock.schedule_once`로 마샬링하고, `show`는 호출 스레드를 오래 막지 않는다.
  `hold` 페이싱은 채널이 이미 담당하므로 여기서 다시 재우지 않는다.
- `KivyCamera(CameraSource)`: `read(timeout)`가 최신 카메라 프레임을 `np.ndarray`로 돌려준다.
  캡처는 `camera4kivy`의 `Preview`(CameraX 기반)에서 받은 최신 프레임 **한 장만 보관**하고
  `read`는 그것을 집어간다 — `Cv2Camera`의 드레인과 같은 목적(신선도 우선, 지연 누적 금지).
  새 프레임이 없을 때의 거동은 `Cv2Camera`와 동일하게 맞춘다(재캡처는 채널의 윈도우 dedup이 흡수).
- **import 가드**: `photontcp/mobile/__init__.py`는 Kivy 부재 데스크톱에서 실패하지 않고
  `KivyDisplay`/`KivyCamera`를 `None`으로 노출하며 `__all__`에서 제외한다 —
  `photontcp/optical/__init__.py`의 cv2 가드와 **동형**으로 쓴다(선례를 그대로 따른다).
- `pyproject.toml`에 optional extra `mobile = ["kivy", "camera4kivy"]`를 추가한다.
- 엣지: 프레임 색공간(카메라 RGBA/YUV → `decode_frame`이 흡수하는 형태)의 변환 지점을 한 곳으로
  모으고, 변환 비용이 캡처 루프에 얹히지 않도록 최신 프레임 1장에만 적용한다.

### M11-T04: Kivy 앱 골격 (deps: M11-T02, M11-T03)

- **변경 파일**: `photontcp/mobile/app.py`(추가), `photontcp/mobile/__init__.py`(수정)
- 화면 구성(최소): 상단 **설정**(role: sender/receiver, `scale`, `hold`, 카메라 facing),
  중앙 **QR 표시 영역**(`KivyDisplay`가 그리는 위젯), 하단 **상태 줄**(`on_event` 콜백이 갱신하는
  진행 상황)과 **시작/중지 버튼**, 종료 후 `established / MATCH / closed / PASS·FAIL` 요약.
- 세션은 **워커 스레드**에서 `run_peer(channel, role, on_event=…)`로 돌린다. UI 갱신은
  `Clock.schedule_once`로 메인 스레드에 마샬링한다(광학 채널은 이미 자체 캡처 스레드를 쓰므로
  스레드 경계를 새로 늘리지 않는다).
- 안드로이드 **런타임 카메라 권한** 요청을 시작 시 처리하고, 거부되면 상태 줄에 사유를 표시한 채
  크래시 없이 멈춘다.
- 데스크톱에서도 실행 가능해야 한다(Kivy 설치 시) — 카메라가 없으면 그 사실을 표시하고 종료한다.
  이 성질이 실기 없이 앱 로직을 눈으로 확인하는 경로가 된다.
- **UI 로직과 세션 로직을 섞지 않는다**: 앱은 `run_peer` 호출과 이벤트 표시만 한다(테스트 가능한
  부분은 전부 T02에 있다).

### M11-T05: `buildozer.spec` + 빌드 파이프라인 문서 (deps: M11-T03)

- `docs/mobile-build.md`: **Docker 경로**(`kivy/buildozer` 이미지)와 **WSL2 경로** 두 가지를 각각

  `adb install`로 폰에 넣는 절차, 실패 시 로그를 어디서 보는지를 포함한다.
- `.gitignore`에 `bin/`·`.buildozer/`를 추가한다(빌드 산출물·툴체인 캐시).
- 이 태스크는 **문서와 스펙**까지다. 실제 빌드 실행은 T06이 맡는다.

- **실패 시(폴백 — M9의 v1.0 폴백 선례를 그대로 따른다)**: 어느 레시피/단계에서 어떤 오류로
  멈췄는지와 로그 요지를 기록하고, 시도한 우회(예: opencv를 requirements에서 빼고 디코더 백엔드
  seam으로 대체 경로 확인)를 함께 적는다. 그 경우 M11은 T06을 제외한 나머지로 판정하며,
  실빌드는 다음 사이클의 첫 항목이 된다. **실패가 마일스톤을 깨지 않는다는 것을 여기서 못박는다.**
- 툴체인 환경(WSL2/Docker 가용 여부)은 착수 시 확인하고, 없으면 그 사실 자체를 위 폴백으로 적는다.

### M11-T07: Micro-QR 원천 제거

- **변경 파일**: `photontcp/qr/encode.py`, `tests/test_qr.py`, `tests/test_qr_robustness.py`,
  `examples/qr_decode_bench.py`
- `encode_frame`이 `segno.make(..., micro=False)`로 **일반 QR만** 내보내게 한다(M10-review 권장 1이
  원인을 인코더로 특정했고, 리뷰가 5·8·9바이트 페이로드의 version-1 100% 디코드를 실측했다).
  `micro`를 인자로 열지 여부는 구현자가 판단하되 **기본은 일반 QR**이다.
- 연동 수정: `test_micro_qr_boundary_excluded`는 "≤9바이트가 실패함"을 단언하므로 **새 사실
  (성공한다)에 맞게 재작성**하고, 코퍼스 하한(≥12B) 제약도 해제하거나 사유를 갱신한다.
- 회귀 확인: 벤치의 디코드율이 이전보다 낮아지지 않아야 한다(완료 기준 2).

### M11-T08: `__version__` 단일 원본 일치화 + 잔여 정리

## 완료 기준

1. **cv2 없이도 import 된다**: cv2 부재를 시뮬레이션한 상태에서 `import photontcp.qr` 성공,
   `encode_frame` 정상 동작, `decode_frame`은 `None` 반환 + 예외 없음(테스트로 단언).
2. **디코드 회귀 없음**: 전체 스위트 그린(기존 188 + 신규), `python examples/qr_decode_bench.py`가
   exit 0이고 "full ≥ base-only on every set"이 유지된다. 깨끗/열화 코퍼스 디코드율이 M10 실측보다
   낮아지지 않는다.
3. **백엔드 seam이 실제로 교체 가능하다**: 가짜 백엔드를 등록·선택하면 `decode_frame`이 그 백엔드를
   호출하고, 선택을 되돌리면 cv2 경로로 복귀한다(결정적 테스트).
4. **CLI 계약 불변**(열거): `examples/optical_link.py --help`가 노출하는 인자 집합이 M10과 동일,
   기본 인메모리 실행 exit 0, `--role sender`(`--real` 없이) exit 2.
5. **`run_peer`가 인메모리에서 왕복을 성립시킨다**: `OpticalChannel.pair()` 위에서 두 role을 구동해
   `established`·`messages_match`·`closed`·`passed`가 모두 참(하드웨어 불필요, 테스트).
6. **모바일 어댑터가 계약을 만족하고 가드가 동작한다**(열거): `issubclass(KivyDisplay, DisplaySink)`,
   `issubclass(KivyCamera, CameraSource)`가 참이고, Kivy 미설치 데스크톱에서 `import photontcp.mobile`이
   성공하며 두 이름이 `None`으로 노출되고 `__all__`에서 빠진다.
7. **`buildozer.spec`이 열거된 항목을 담는다**: `package.name`, `package.domain`, 진입점,
   `requirements`(opencv 포함 여부와 사유가 주석으로 명시), `android.permissions = CAMERA`,
   `android.archs = arm64-v8a`.
8. **`docs/mobile-build.md`가 두 경로를 각각 명령 단위로 적는다**: Docker 경로와 WSL2 경로,
   `adb install` 절차, 실패 시 로그 위치.
9. **APK 빌드 결과가 기록된다**: 성공이면 APK 경로·크기·소요 시간·requirements 실측을,
   실패면 멈춘 레시피/단계·오류 요지·시도한 우회를 impl 보고서에 적는다. **실패는 이 마일스톤을
   깨지 않는다**(M9의 v1.0 폴백 선례) — 다만 그 경우 판정은 T06을 제외한 범위로 내린다.
10. **Micro-QR 블라인드스폿이 원천 제거된다**: 5·8·9바이트 페이로드가 `encode_frame` →
    `decode_frame` 왕복 100% 성공하고, 기존 `test_micro_qr_boundary_excluded`가 새 사실에 맞게
    재작성돼 통과한다.
11. **버전 선언처가 하나다**: `photontcp/__init__.py`와 `pyproject.toml`이 갈라지면 실패하는
    테스트가 존재하고 통과한다.
12. **실기 실측은 이번 범위 밖임이 문서에 남는다**: `docs/v1.0-signoff.md`에 폰+PC 체크 B 절차가
    추가되고, 실측 수행은 다음 사이클 항목으로 명시된다.
