# tide 개발 규약 (PhotonTCP)

이 문서는 tide 개발 사이클을 따르기 위한 프로젝트 로컬 규약을 기록한다.
마일스톤·보고서의 **형식 원본**은 이 문서가 아니라 tide 플러그인 각 스킬에 동봉된
`template.md` 가 단일 원본(single source of truth)이다. 여기서는 형식을 재정의하지 않는다.

## 단계(phase)별 금지 행위

tide 사이클은 단계로 나뉘며 각 단계에서 허용/금지되는 행위가 다르다.

- **milestone**: 다음 작업 단위를 문서로 정의한다. 코드 구현·git 작업 없음.
- **impl**: 마일스톤대로 구현 + 테스트 + 완료 보고서 작성.
  - 🚫 **git 작업 금지** (add/commit/tag/push 등 일절 하지 않는다).
- **review**: 최근 구현을 비판적으로 리뷰 + 리뷰 보고서 + 릴리즈 판정.
  - 🚫 **git 작업 금지** (커밋·태그·푸시 없음).
- **release**: 프리플라이트 → 버전 범프 → CHANGELOG → commit → tag → push.
  - ✅ git 작업은 **release 단계에서만** 수행한다.
- **debug**: 발견한 에러를 **세션 단위**로 묶어 수정·누적 + debug 보고서 + 릴리즈 판정.
  - 🚫 **git 작업 금지** (커밋·태그·푸시 없음).
  - 열린 debug 세션이 있으면 release는 중단된다 — `/tide:debug done`으로 먼저 닫는다.

> git 작업 차단 가드(tide-guard)는 tide 플러그인이 hook으로 직접 제공한다.
> 프로젝트별 hook 설치는 필요 없으며, 별도 설치 절차를 만들지 않는다.

## 상태 파일 규약

`.tide/` 아래 파일은 **무시 대상 둘 · 커밋 대상 셋**으로 갈린다. `.tide/` 디렉터리 전체를
무시하지 않는 이유가 이것이다.

**무시(로컬 상태)** — `.gitignore` 처리 대상은 아래 **둘뿐**이다.

- `.tide/phase` : 현재 사이클 단계 **한 줄**.
  값 집합은 `milestone` / `impl` / `review` / `release` / `debug` / `idle` 이며,
  각 커맨드가 시작 시 자기 단계를 기록하고 최종 보고 직전 `idle`로 되돌린다.
- `.tide/debug-session` : 열린 debug 세션의 **활성 보고서 번호 한 줄**(예: `3`).
  파일 존재 = 세션 열림이고 `/tide:debug done`이 닫으며 삭제한다.
  세션 번호를 별도 파일에 두므로 `.tide/phase`는 종전대로 **단계명 한 줄**만 담는다.

**커밋(선언·선호도)** — 아래 셋은 무시하지 않는다.

- `.tide/deps` : 레포 간 의존을 **한 줄에 형제 레포명 하나씩** 선언하는 **선택·옵트인** 매니페스트.
  선언 시 fleet이 위상정렬해 권장 처리 순서를 제시한다. 없으면 의존 0(기본 동작).
  kickoff가 이 파일을 자동 생성하지는 않는다.
- `.tide/release-mode` : 릴리즈 게시 모드 선호도(한 번 묻고 기억한 뒤 자동).
  현재 값: `release`.
- `.tide/autonomy` : 자율 진행 수준 **한 줄**(`manual` / `continuous`).
  **파일이 없으면 `manual`과 같다** — 부재가 곧 현행 동작이라 이 저장소에는 파일이 없다.
  `continuous`면 `/tide:cycle`이 release 직전이 아니라 **커밋 앞**에서 멈춘다.
  release-mode와 동급으로 커밋한다(둘 다 팀이 공유하는 진행 방식 선호도).

## 태스크 ID · 의존성 표기

- 마일스톤 내 작업 항목은 안정적인 **태스크 ID**로 식별한다 (예: `T1`, `T2`, ...).
- 작업 간 의존은 `(deps: T1, T2)` 형태로 항목에 표기한다. 의존 표기가 있으면
  impl/cycle이 이를 근거로 병렬/순차 실행 순서를 정한다.

## 버전 파일 위치

- 버전 단일 원본: **`pyproject.toml`** 의 `[project].version`.
- release 단계의 버전 범프·CHANGELOG 갱신은 이 파일을 기준으로 한다.
- 현재 버전 값은 **이 문서에 복제하지 않는다** — `pyproject.toml`을 직접 읽는다.
  (복제하면 릴리즈마다 낡는다. `tests/test_docs_no_version_dup.py`가 재발을 문다.)

## 디렉터리

- `docs/milestones/` : 마일스톤 문서.
- `docs/reports/`    : impl 완료 보고서 · review 리뷰 보고서.
- `docs/project-context.md` : 코드베이스 개요 캐시 + **이월 항목 처분 원장**.
  `/tide:milestone`·`/tide:impl`이 있으면 먼저 읽어 매번 재조사하지 않는다(필수 전제조건은 아니다).
- `docs/epics/` : 에픽(방향) 층 — **옵트인**이다. 없으면 현행 동작 그대로이며,
  이 저장소는 아직 두지 않는다.

## 리뷰 검증 규율 (요지)

전문의 **단일 원본은 설치된 tide 스킬의 규약**이다. 여기서는 이 저장소가 그 규율 아래
돈다는 사실과 요지만 적는다(문서 복제 드리프트를 만들지 않는다).

- **반증 시도 (refutation)** — `/tide:review`는 판정을 만들기 전에 판정 후보를 **스스로 공격하는
  독립 패스**를 거치고, 그 결과를 리뷰보고서의 **계측 줄**에 남긴다.
- **재검증 (re-verify)** — 리뷰가 리뷰 중에 직접 고친 것은 고친 사람이 다시 검증한다.
- **재작업 라운드 (rework)** — 판정 `불가` 후의 재실행은 재작업 라운드로 센다.

### 차단 등급 판례

- **`vacuous-pass`** — 가드·검증이 **공허하게 통과**하거나, 문서·규약이 **집행력을 사실보다 넓게**
  주장하면 그 지적은 **차단** 등급이다.
- **`precedent-waiver`** — 위 판례 부류에 가깝다고 보면서도 차단으로 매기지 않기로 했다면
  그 **부인을 기록**한다.

## 회고 후속 항목의 소비

- **단일 원본**: 회고 문서(`docs/reports/retro.md`)의 **「후속 항목 추적」 표**가 후속 항목 상태를
  적는 유일한 자리다. 상태 값 집합은 `반영` / `미반영` / `미결` / `처분` 이다.
- 그 표는 ASCII 마커 `<!-- retro-followups:start -->` … `<!-- retro-followups:end -->` 로 여닫는다.
  **문서 전체에서 창은 정확히 하나** — 최상단(최신) 회고 섹션에만 두고, 새 섹션을 쌓을 때
  직전 섹션의 **여닫는 두 줄만** 걷는다(표 내용은 이력으로 보존).
- **소비자는 `/tide:milestone` 하나다** — 상태가 `미반영`·`미결`인 행을 읽고 새 마일스톤이
  무엇을 집는지 보고에 남긴다. **막지 않는다 — advisory다.**
- `/tide:retro`가 어떤 행을 `처분`으로 옮기면 **같은 편집에서** `docs/project-context.md`의
  **이월 항목 처분 원장**에 사유 한 줄을 남긴다. 회고가 여는 쓰기는 그 한 줄뿐이다.

## debug 세션

- `/tide:debug [증상]`이 세션을 열고 `.tide/debug-session`에 활성 보고서 번호를 기록한다.
  이후 발견되는 에러는 같은 세션의 보고서(`docs/reports/debug-N.md`)에 누적된다.
- `/tide:debug done`이 개요·판정을 채워 보고서를 마무리하고 `.tide/debug-session`을 삭제한다.
- **열린 세션이 있으면 `/tide:release`는 중단된다** — 먼저 `done`으로 닫는다.
- debug 단계도 git 작업은 하지 않는다(커밋·태그·푸시 없음).

## 멀티 레포 / 대상 레포 규약

- 모든 tide 산출물(골격, `docs/project-context.md`, `.gitignore`, `CHANGELOG.md`, 마일스톤·
  보고서 등)은 **대상 레포 루트**에 만든다.
- **기본**: 대상 레포 = 세션 레포(현행 단일 레포 동작 그대로).
- **상위 폴더 단일 세션**에서 특정 자식 레포를 지시받으면, 그 **자식 레포 루트**가 대상 레포가 된다.
- 격리 원칙: 한 사이클의 산출물은 다른 레포 루트를 침범하지 않는다.

### 멀티 레포 오케스트레이션 (발견)

fleet 계열 스킬이 자식 tide 레포를 발견할 때의 판별 규칙:

- **세는 대상**: 현재 세션 위치(cwd)의 **직속 1단계 하위 디렉터리**.
- **자식 tide 레포 판별**: 해당 하위 디렉터리가 tide 골격(예: `docs/conventions.md` 및
  `docs/milestones/`·`docs/reports/` 구조)을 갖추고 있으면 자식 tide 레포로 본다.
- **제외**: 이름이 `.` 으로 시작하는 숨김 디렉터리는 세지 않는다.
- 자식 tide 레포가 **2개 이상**일 때만 교차 집계(fleet)가 의미를 갖는다.
  2개 미만(0·1개)이면 일반 단일 레포로 동작한다.
